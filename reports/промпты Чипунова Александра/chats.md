

## Рефакторинг оркестратора
```
задача зарефакторить один наш внутренний инфраструктурный компонент. Это интерактивная песочница, работающая по схеме Docker-in-Docker (DinD).

Как это устроено сейчас:
На уровне контейнера L1 крутится наш внутренний оркестратор — демон sandboxd. Его задача — динамически поднимать дочерние контейнеры L2 (в коде они называются node), настраивать между ними сеть, маршрутизацию и вообще рулить всем коннектом.
Для ручного управления из L1 пока сделана временная затычка — CLI-утилита sandboxd-cli (или SandboxdShell). Она нужна на время, пока мы не запилим полноценное внешнее API. Текущее API демона смотрит только внутрь — на контейнер с ИИ-агентом (agent), и сам агент общается с внешним миром только через логи и запросы к этому самому sandboxd.

Что по состоянию системы:
На данном этапе все работает, сеть выстраивается, коннект есть. Из известных багов — иногда при docker compose up без флага --build (а порой и с ним) система ругается на занятые PID внутри контейнера и не поднимается с первого раза. Баг не критичный, встречается при падении контейнера.
Важный момент: документация в .md файлах местами устарела. Если видишь расхождения между описанием контрактов в доке и реальным поведением — верь коду. Код сейчас является первоисточником истины.

Что конкретно нужно сделать (Задача):
Ломать и перекраивать кор-механики оркестрации и сети нельзя, иначе мы уползем от планового функционала или вообще всё развалим. Нужен именно аккуратный, «мягкий» рефакторинг.
Не надо городить огород из миллиарда абстракций, фабрик и классов. Нужно просто прибраться:

* Сделать код более целостным, чистым и читаемым.
* Внедрить интерфейсы буквально в паре-тройке самых нужных мест, где это явно напрашивается.

* В апи-морду демона тоже можно заглянуть, но там вроде бы все более-менее ок, так что без фанатизма.

Я скидываю архив с модулями. Там сам sandboxd (его рефакторим), папка packages со схемами, композ-файлы и манифесты. Еще закинул код ИИ-агента — его рефакторить не нужно, он лежит просто для контекста, если вдруг понадобится посмотреть, как он дергает демон.

И держи в уме на будущее: это песочница, поэтому в перспективе этот DinD-контур мы будем сильно зажимать по разрешениям (cgroups, capabilities и т.д.). Мы идем к максимальной изоляции, так что архитектура должна этому соответствовать.
```

````
Сделал именно мягкий рефакторинг, без перестройки архитектуры вокруг «миллиарда абстракций».

### Что поменял

**Оркестратор**

* `SandboxOrchestrator` теперь отвечает именно за topology/lifecycle, а Docker-детали вынесены в runtime.
* `ContainerRuntime` стал реально используемым `Protocol`.
* Добавлены:

  * `aliases()`
  * `started`
  * нормальная валидация manifest'ов;
  * rollback при частичном `start()`;
  * cleanup контейнера, если после запуска упало подключение дополнительной сети;
  * более аккуратный `stop()`.
* Убрана зависимость оркестратора от внутреннего `_client` Docker насколько это возможно.
* `NodeInstance` получил нормальный `id`, а `raw_access` оставлен как legacy escape hatch.

Ключевая граница теперь такая:

```python
class ContainerRuntime(Protocol):
    def up(self, manifest: NodeManifest) -> Container: ...
    def down(self, container: Container) -> None: ...
    def remove_container(self, name: str) -> None: ...

    def create_network(self, name: str, *, internal: bool) -> None: ...
    def remove_network(self, name: str) -> None: ...
    def connect(self, container: Container, network: str) -> None: ...
```

А `NodeRunner` — конкретная Docker-реализация этого runtime.

---

**NodeRunner**

* Оставил прежнюю механику `build → run → healthcheck`.
* Разнёс build/network/container/healthcheck по понятным секциям.
* HTTP healthcheck теперь использует один `httpx.Client`.
* Dockerfile теперь учитывается в image hash **по содержимому**, а не только по имени.
* Hash переведён на SHA-256.
* Убраны дубли и кривые куски вроде двойного формирования `ports`.
* `get_ip()` больше не дублируется в двух местах.
* Ошибка на healthcheck по-прежнему приводит к удалению контейнера.

---

**Конфигурация**
Вместо километров констант в `SandboxShell` появился:

```text
sandboxd/src/sandboxd/config/settings.py
```

Туда вынесены:

* project root;
* директория логов;
* имена сетей;
* порты;
* Ollama/LLM;
* включение LLM bridge;
* задержка `tc`.

Например:

```bash
SANDBOXD_TARGET_NETWORK
SANDBOXD_CONTROL_NETWORK
SANDBOXD_EGRESS_NETWORK
SANDBOXD_AGENT_PORT
SANDBOXD_GATEWAY_PORT
SANDBOXD_LLM_BRIDGE
SANDBOXD_EGRESS_DELAY_MS
OLLAMA_BASE_URL
OLLAMA_MODEL
LLM_UPSTREAM_HOST
LLM_UPSTREAM_PORT
```

При этом дефолты оставлены такими, чтобы существующая PoC-топология не менялась.

---

**SandboxShell**

* Убраны все project/network/env константы из самого shell.
* Shell теперь в основном занимается только человеческим интерфейсом.
* Использует `orchestrator.started` и `aliases()`, а не собственное дублирование состояния.
* Нормализован `status`, `exec`, `logs`, `watch`.
* Сохранил все текущие команды и логику ручного управления.
* Агентскую реализацию не рефакторил.

---

**DIND / Docker**
Тут было несколько объективных проблем.

В частности, архив содержит структуру:

```text
sandboxd/
pentest_agent_test/
packages/
```

а Dockerfile и часть Dockerfile'ов продолжали ссылаться на старое:

```text
apps/sandboxd/
apps/pentest_agent_test/
```

Это исправлено.

Также исправлено:

* дублированное `apk add`;
* `uv sync --frozen` при отсутствии `uv.lock`;
* workspace, который смотрел в `apps/*`, хотя таких workspace members в архиве уже нет;
* `PYTHONPATH` agent image;
* `COPY` в gateway image;
* PID/socket cleanup перед запуском nested `dockerd`;
* явный `DOCKER_HOST` на внутренний daemon;
* ожидание `dockerd` вынесено в более аккуратный readiness loop;
* `tc qdisc add` заменён на `tc qdisc replace`, что как раз убирает один класс проблем с повторным запуском;
* LLM bridge теперь можно отключить переменной окружения, хотя по умолчанию он включён.

При этом **`privileged: true` и `cgroup: host` я не трогал**. Для текущего PoC это правильно: не надо притворяться, что sandbox уже умеет работать в будущем hardened-режиме. Зато граница сейчас достаточно чистая, чтобы позднее заниматься capabilities/cgroup отдельно.

### Важный момент

Я **не менял саму модель сети**:

```text

          ├── sandbox-target-net
          ├── sandbox-control-net
          └── sandbox-egress-net

gateway
   └── sandbox-control-net
```

и не стал внедрять какие-нибудь сервисные registry, event bus, dependency injection framework и прочую архитектурную хуйню, которая здесь пока только мешала бы.
````
